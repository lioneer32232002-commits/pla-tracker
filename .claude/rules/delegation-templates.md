# 派工 Prompt 模板

> 用法：複製對應模板，填掉所有 `{…}` 空格，**不留任何空格未填**再送出。
> 通用規則見 [model-dispatch.md](model-dispatch.md)：三件套、回報合約、升降級。
> 每個模板末尾的「回報合約」段落原文保留，不要刪。

## 共用尾段（每個派工 prompt 結尾都貼這段）

```
回報合約：你的回報只能包含：結論（≤10 行）、關鍵證據的 檔案:行號、你改動的
檔案清單、未解決事項。禁止貼整段程式碼或整份檔案。長產物寫進 {落檔路徑，
預設 scratchpad}，回傳路徑。沒把握的部分標「不確定」，不要編造。
```

## 1. 搜尋／盤點（agent type: `Explore`，model: sonnet；純機械匹配可 haiku）

```
目標：找出 {要找什麼，具體到字串/模式/概念}。
動機：{主對話為什麼需要這個，會拿去做什麼決定}。
範圍：{目錄或檔案清單；沒把握就寫「整個 repo，但跳過產出 HTML 與 charts/」}。
搜索廣度：{medium｜very thorough——找「所有出現位置」必用 very thorough}。
驗收條件：每個結果附 檔案:行號；明確說明「找完了」還是「可能有漏」及原因。
找不到也是合法答案，要說明找過哪些變體。
```

---

## 2. 實作（agent type: `general-purpose`，model: sonnet；跨檔疑難用 opus）

```
目標：{要實作什麼，一句話}。
動機：{使用者原始需求＋為什麼選這個做法}。
已知脈絡：{相關檔案與行號、既有慣例、必讀的規則檔路徑}。
硬約束：{本專案鐵律中相關者，例如「產出 HTML 禁止手改」「禁止在 build 加字型」}。
做法：{已決定的方案；若留給 subagent 決定，寫明決策邊界}。
驗收條件（全部要達成並附執行證據）：
- python -X utf8 scripts/validate.py all 通過
- {功能面的具體可驗證行為，例：「index.html 內含 xxx 字串」「preview 載入無 console 錯誤」}
- 不 commit 不 push（由主對話統一處理）
```

> 注意：「不 commit 不 push」只約束 subagent。主對話收到成果並驗收後，
> 仍須照 CLAUDE.md 鐵律 5 立即 commit＋push。

## 3. 重構／批次套用（agent type: `general-purpose`，model: haiku 或 sonnet）

> 前提：改法已在一個檔案上驗證過。沒有已驗證範例就不是批次任務，回模板 2。

```
目標：把以下已驗證的修改模式套用到 {檔案清單}。
範例（已驗證正確）：
{貼上該檔案的 before/after diff}
規則：{哪些情況照套、哪些情況跳過並回報，邊界要窮舉}。
驗收條件：每個檔案改完後 {驗證指令}；有任何一個檔案不符合範例模式 → 不要
自行發明改法，跳過並在回報中列出。
```

## 4. 研究／查外部資料（agent type: `general-purpose`，開頭註明可用 WebSearch/WebFetch）

```
問題：{要回答的具體問題，可判定「答到了沒」的形式}。
動機：{要支持什麼決定}。
驗收條件：
- 每個結論附來源 URL 與發布日期
- 區分「來源明說的」與「你推論的」
- 找不到可靠來源 → 回報「查無」＋查過的關鍵字，禁止用訓練記憶充當查證結果
產出：{≤1 頁摘要直接回報｜寫入 {路徑} 回傳路徑}。
```

---

## 5. 審查／驗收（agent type: `general-purpose`，model: 不低於被審產物的產出模型）

> Fresh-context 原則：只給驗收條件與產物位置，**不要**貼原派工 prompt 或
> 「我是這樣做的」描述，避免審查者被帶風向。

```
你是驗收者，之前的對話你都沒看過，只依下面的條件獨立檢查。
待審產物：{檔案路徑或 diff 範圍}。
驗收條件：{逐條列出，來自原派工的驗收條件}。
檢查方式：
- 文件 → 逐條 read-back：條件對應到檔案哪一段，引 檔案:行號
- 程式碼 → 實跑 {驗證指令}，並主動想 2 個邊界情況測試
- 另外回答：有沒有條件之外、但會讓使用者不滿意的問題？
結論格式：PASS 或 FAIL；FAIL 要列出每個未達條件＋證據位置。傾向嚴格：
不確定算 FAIL。
```
